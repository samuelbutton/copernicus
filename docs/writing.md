# Writing guide

Use [ASD-STE100, Issue 9](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf) for new project documents.
Keep legal notices and exact command syntax unchanged.

## Sentences and procedures

Use active voice and give each sentence one topic.
Keep instructions within 20 words and descriptions within 25 words per sentence.
Give each paragraph one topic and no more than six sentences.
Use the same term for the same concept.
Define necessary technical terms in the [glossary](glossary.md).

Give each procedure its prerequisites, working directory, commands, expected result, and cleanup steps.
Explain failures beside the relevant command.
Distinguish available behavior, illustrative examples, and planned features.
Provide all necessary context inside this public repository.
Lead project summaries with plain language before technical details.

## Names and examples

Use Copernicus for this project and Yamata for the public execution boundary.
Use generic names for other organizations, people, systems, and examples.
Relevant public technology names and required repository or license metadata retain their correct names.
Do not include private source notes, former employer names, private system names, aliases, or private links.
Apply these rules to code, comments, paths, output, examples, diagrams, and documents.

## Review

Prerequisites: the changed text, glossary, and standard's rules and dictionary.

1. Read each sentence for its intended meaning.
2. Check word meanings, technical terms, sentence length, and paragraph length.
3. Check active voice and consistent terminology.
4. Review names, links, diagrams, and examples for private references.
5. Run changed command examples and compare their outputs with the descriptions.
6. Run each procedure's cleanup steps.

The expected result is accurate, self-contained documentation with repeatable examples.
Text searches and word counts support review but cannot prove compliance.
